Умная система мониторинга качества воздуха с машинным обучением

Создание системы, которая мониторит качество воздуха в помещении и на улице, анализирует данные с помощью машинного обучения и предоставляет рекомендации по улучшению качества воздуха. Эта система может быть полезной для домов, офисов, школ и других помещений, где качество воздуха является важным фактором для здоровья.

Необходимые компоненты

  • Микроконтроллер ESP32 — встроенный Wi-Fi и Bluetooth, высокая производительность для обработки данных
  • Датчики качества воздуха:
    • MQ-135 — измеряет уровень CO₂, NH₃, NOₓ и других газов
    • DHT22 — измеряет температуру и влажность
    • PM2.5 датчик — измеряет концентрацию мелких частиц в воздухе
  • Блок питания — подходящий источник питания для микроконтроллера и датчиков (5В/2А рекомендуется)
  • ЖК-дисплей или OLED-дисплей — для отображения данных в реальном времени (опционально)
  • Облачная платформа — например, ThingSpeak для хранения и анализа данных
💡Совет: Для точных измерений калибруйте датчик MQ-135 в течение 24–48 часов после первого включения — он требует прогрева для стабильных показаний.

Шаги реализации

  1. Сборка аппаратной части:
    • Подключите датчики к ESP32 согласно схеме подключения
    • Подключите ЖК-дисплей для отображения данных (опционально)
    • Обеспечьте стабильное питание всех компонентов
  2. Программирование микроконтроллера:
    • Напишите код на Arduino IDE или MicroPython для считывания данных с датчиков
    • Реализуйте отправку данных на облачную платформу (ThingSpeak, Blynk, MQTT)
    • Используйте библиотеки для работы с датчиками (Adafruit Sensor, DHT library)
  3. Обработка данных и машинное обучение:
    • Сохраняйте данные на облачной платформе для последующего анализа
    • Используйте Python с библиотеками scikit-learn или TensorFlow для обучения модели
    • Создайте алгоритм, который анализирует данные и предлагает рекомендации по улучшению качества воздуха
  4. Интерфейс пользователя:
    • Создайте веб-интерфейс или мобильное приложение для отображения данных в реальном времени
    • Добавьте визуализацию трендов и уведомления при ухудшении качества воздуха
    • Реализуйте систему рекомендаций (проветрить помещение, включить очиститель и т.д.)

Схема подключения датчиков к ESP32

  1. DHT22 (температура/влажность):
    • VCC → 3.3V
    • GND → GND
    • DATA → GPIO 14
  2. MQ-135 (качество воздуха):
    • VCC → 5V
    • GND → GND
    • AOUT → аналоговый вход GPIO 34 (ADC1_CH6)
  3. PM2.5 датчик (например, PMS5003):
    • VCC → 5V
    • GND → GND
    • Tx → GPIO 16 (UART2 RX)
    • Rx → GPIO 17 (UART2 TX)
  4. OLED-дисплей (опционально, I2C):
    • VCC → 3.3V, GND → GND
    • SCL → GPIO 22, SDA → GPIO 21
ℹ️Примечание: GPIO 34, 35, 36, 39 на ESP32 поддерживают только аналоговый ввод (ADC) и не имеют внутренних подтяжек — используйте внешние резисторы при необходимости.

Пример кода: считывание данных и отправка на ThingSpeak

Пример кода на MicroPython для считывания данных с датчиков и отправки их на облачную платформу ThingSpeak:

import network
import urequests
from machine import Pin, I2C, ADC
import dht
import time

# Подключение к Wi-Fi
ssid = 'your_SSID'
password = 'your_PASSWORD'

wlan = network.WLAN(network.STA_IF)
wlan.active(True)
wlan.connect(ssid, password)

while not wlan.isconnected():
    pass

print('Connected to WiFi')

# Инициализация датчиков
dht_sensor = dht.DHT22(Pin(14))

# Аналоговый вход для MQ-135
mq135 = ADC(Pin(34))
mq135.atten(ADC.ATTN_11DB)  # Полная шкала 0-3.3В

# I2C для OLED (опционально)
i2c = I2C(scl=Pin(22), sda=Pin(21))

# URL для отправки данных на ThingSpeak
thingspeak_url = 'https://api.thingspeak.com/update?api_key=YOUR_API_KEY'

while True:
    try:
        # Чтение DHT22
        dht_sensor.measure()
        temp = dht_sensor.temperature()
        hum = dht_sensor.humidity()
        
        # Чтение MQ-135 (аналоговое значение)
        mq_value = mq135.read()
        # Конвертация в условные единицы качества воздуха (калибровка требуется)
        air_quality = mq_value / 4095 * 100
        
        # Формирование запроса для отправки данных
        response = urequests.get(
            thingspeak_url + 
            f'&field1={temp}' +      # Температура
            f'&field2={hum}' +       # Влажность
            f'&field3={air_quality}' # Качество воздуха
        )
        print(response.text)
        response.close()
        
    except OSError as e:
        print('Failed to read sensor:', e)
    
    time.sleep(60)  # Отправка данных каждые 60 секунд
❗Важно: Датчик MQ-135 требует калибровки в чистом воздухе для точных измерений. Запишите базовое значение в хорошо проветриваемом помещении и используйте его как точку отсчёта.

Машинное обучение для анализа данных

После сбора данных на облачной платформе можно приступить к их анализу с помощью машинного обучения:

  • Подготовка данных: Экспортируйте данные из ThingSpeak в CSV-формат и очистите их от выбросов
  • Выбор модели: Для классификации качества воздуха подойдёт Random Forest или нейросеть; для прогнозирования — LSTM или ARIMA
  • Обучение: Разделите данные на обучающую и тестовую выборки, обучите модель на исторических данных
  • Развёртывание: Экспортируйте модель в формат TensorFlow Lite для запусков на ESP32 или оставьте обработку на сервере
# Пример: простая классификация качества воздуха на Python
from sklearn.ensemble import RandomForestClassifier
import pandas as pd

# Загрузка данных
data = pd.read_csv('air_quality_data.csv')

# Подготовка признаков и целевой переменной
X = data[['temperature', 'humidity', 'mq135_value', 'pm25']]
y = data['quality_label']  # 'good', 'moderate', 'poor'

# Обучение модели
model = RandomForestClassifier(n_estimators=100, random_state=42)
model.fit(X, y)

# Прогноз для новых данных
new_data = [[24.5, 45, 1200, 35]]  # temp, hum, mq135, pm2.5
prediction = model.predict(new_data)
print(f'Качество воздуха: {prediction[0]}')

Возможные проблемы и решения

  • Датчики показывают нестабильные значения:
    • Дайте датчику MQ-135 прогреться 24–48 часов перед калибровкой
    • Используйте усреднение нескольких измерений для сглаживания шума
    • Размещайте датчики вдали от источников тепла и сквозняков
  • ESP32 теряет соединение с Wi-Fi:
    • Добавьте переподключение в коде при потере соединения
    • Используйте WDT (Watchdog Timer) для перезагрузки при зависании
    • Проверьте стабильность питания (добавьте конденсатор 100 мкФ)
  • Модель машинного обучения даёт неточные прогнозы:
    • Увеличьте объём обучающих данных (минимум несколько недель измерений)
    • Добавьте больше признаков: время суток, день недели, сезон
    • Проведите кросс-валидацию и настройку гиперпараметров
